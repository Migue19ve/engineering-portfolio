# Using this portfolio in job applications

Preferred link: **https://github.com/Migue19ve/engineering-portfolio**

Use this specific repository as the public work sample. Do not substitute a broad GitHub profile link or link to private work. Do not grant access to client repositories, upload internal screenshots, or forward proprietary source code.

## Short introduction

> My public portfolio contains three original demos with fictional data: a fault-tolerant event-processing simulation, a CSV validation and quoting workflow, and a read-only assistant with visible tool traces. Each includes runnable code, screenshots, tests, and implementation tradeoffs.

## Choose the relevant example

| Role | Lead with | Accurate description |
| --- | --- | --- |
| Backend / infrastructure | Reliable integrations | A local transactional simulation demonstrating retries, replay protection, stale revisions, and conflicting writes |
| Full-stack / automation | Data to decisions | An interactive CSV validation workflow with precise totals, row-level feedback, and export gating |
| AI / integration engineer | Transparent assistant | A deterministic demonstration of read-only tools and evidence-backed answers; no live LLM |

Describe these as **portfolio demonstrations**, not customer deployments. Do not claim uptime, throughput, revenue impact, or production adoption from these exercises. Keep actual employment history and achievements grounded in separately verified résumé information.

## Publication rule

New examples must be built from scratch with invented data. Every screenshot must be captured from the demo, with no private tabs, notifications, account details, client branding, or infrastructure addresses. Review every tracked file and Git history before publishing.

Nothing here authorizes automatic applications, recruiter messages, or follow-up emails. Those require a user request.

## Preparing an authorized application

1. Use discovery boards to find leads, then read the employer's current posting. Confirm the allowed work locations and compensation; a US salary range may be adjusted elsewhere.
2. Check existing application records before submitting. A different role at the same company is distinct; a repeat of the same role must be identified as a reapplication.
3. Match the introduction to one relevant example above and verified employment experience. Keep the demonstration's behavior separate from actual professional achievements. Do not invent measured impact or expertise in unfamiliar technology.
4. Keep residence, work authorization, employer sponsorship, and contractor eligibility separate. A planned arrangement does not establish current authorization.
5. Review the complete answers and uploaded document before submitting. Confirm the employer's success screen or verify the sent application email; an email send does not establish employer receipt.
6. Store the role URL, date, submitted answers, compensation conditions, and confirmation privately. Keep incomplete forms and applications awaiting a verification step out of the completed count.

This process supports focused applications in batches. Response rates and interview conversion can only be evaluated after employers have had time to reply.
